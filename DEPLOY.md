# Dokploy Deployment Guide for Hartbeat Harmony

## Prerequisites

Before deploying, ensure you have:

1. **VPS Access** with Dokploy installed and running
2. **Domain Names** pointed to your VPS IP address (DNS A records):
   - `api.YOURDOMAIN.com` → Your VPS IP
   - `admin.YOURDOMAIN.com` → Your VPS IP
3. **Email SMTP Credentials** for `support@ICSNCardiology.org` (or whichever email you will use)
4. **Database URL** (Neon PostgreSQL recommended, or local Postgres)

## Architecture

```
User → Traefik (Dokploy) → Services
├─ api.domain.com → Backend (Django + Daphne + Socket.IO) :8005
├─ admin.domain.com → Frontend (Next.js Admin Panel) :3004
└─ [*internal*] → Redis :6379
```

**Features Deployed:**
- **Backend API** with JWT Authentication
- **Admin Dashboard** (Next.js)
- **WebSocket / Socket.IO** for real-time chat
- **Media Uploads** persisted via Docker volumes
- **SMTP Email** for OTP sending
- **Auto SSL** via Let's Encrypt (Traefik)

## Step 1: Configure Environment Variables

Copy the example file and fill in your real values:

```bash
cp .env.dokploy.example .env.dokploy
nano .env.dokploy
```

### Required Fields to Fill:

| Variable | Example Value |
|----------|---------------|
| `API_DOMAIN` | `api.icsncardiology.org` |
| `FRONTEND_DOMAIN` | `admin.icsncardiology.org` |
| `SECRET_KEY` | Generate with `python -c "import secrets; print(secrets.token_urlsafe(50))"` |
| `DATABASE_URL` | Your Neon PostgreSQL URL or local Postgres URL |
| `EMAIL_HOST_PASSWORD` | Password for `support@ICSNCardiology.org` |

### SMTP Settings for Common Providers:

**Hostinger Email:**
```
EMAIL_HOST=smtp.hostinger.com
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_HOST_USER=support@ICSNCardiology.org
```

**Google Workspace:**
```

EMAIL_HOST_USER=support@ICSNCardiology.org
```

**Namecheap Private Email:**

```
EMAIL_HOST_USER=support@ICSNCardiology.org
```

## Step 2: Push to Git Repository

Dokploy deploys from a Git repository. Push your project to GitHub/GitLab:

```bash
git add docker-compose.dokploy.yml frontend/Dockerfile .env.dokploy.example DEPLOY.md
git commit -m "Add Dokploy deployment configuration"
git push origin main
```

## Step 3: Create Dokploy Compose Application

1. Log into your Dokploy web panel (`https://your-vps-ip:3000` or your configured domain)
2. Go to **Projects** → Create New Project (e.g., "Hartbeat Harmony")
3. Click **Add Service** → **Compose**
4. Fill in:
   - **Name:** `hartbeat-harmony`
   - **Repository:** Your Git repo URL
   - **Branch:** `main`
   - **Compose File Path:** `docker-compose.dokploy.yml`
5. Click **Create**

## Step 4: Set Environment Variables in Dokploy

1. In the Dokploy service panel, go to the **Environment** tab
2. Click **Advanced** mode
3. Paste all variables from your `.env.dokploy` file
4. Click **Save**

Example format in Dokploy:
```
API_DOMAIN=api.icsncardiology.org
FRONTEND_DOMAIN=admin.icsncardiology.org
SECRET_KEY=your-generated-secret
DATABASE_URL=postgresql://...
EMAIL_HOST_PASSWORD=your-email-password
```

## Step 5: Configure Domains

1. In the Dokploy service panel, go to the **Domains** tab
2. Dokploy should automatically detect Traefik labels from `docker-compose.dokploy.yml`
3. Verify both domains are listed:
   - `api.YOURDOMAIN.com` → Backend service
   - `admin.YOURDOMAIN.com` → Frontend service
4. SSL certificates will be auto-generated by Let's Encrypt

## Step 6: Deploy

1. Click **Deploy** in the Dokploy service panel
2. Dokploy will:
   - Pull the repository
   - Build Docker images for backend and frontend
   - Start Redis, Backend, and Frontend containers
   - Configure Traefik routing and SSL

3. Monitor the **Logs** tab for each service to ensure successful startup

## Troubleshooting

### Issue: Frontend shows "API Error" or cannot connect

**Fix:** Ensure `NEXT_PUBLIC_API_BASE_URL` was set during build. In Dokploy, rebuild the frontend service after confirming env vars are set.

### Issue: WebSocket connection fails

**Fix:**
1. Check that Redis is running: `docker ps | grep redis`
2. Check Socket.IO URL in Flutter is using `https://api.YOURDOMAIN.com` not `ws://`
3. Traefik auto-handles WebSocket upgrades, but verify the route is going to backend:8005

### Issue: Email OTP not sending

**Fix:**
1. Check backend logs in Dokploy for SMTP errors
2. Verify `EMAIL_HOST_PASSWORD` is correct (some providers require app-specific passwords)
3. Test SMTP credentials independently:
   ```bash
   telnet smtp.hostinger.com 587
   ```

### Issue: Media uploads not persisting

**Fix:** Volumes `media_volume` and `static_volume` are defined. If media disappears after redeploy, ensure Dokploy is not pruning volumes. Use named volumes in Dokploy settings.

### Issue: CORS errors

**Fix:** Verify `CORS_ORIGINS` and `CSRF_TRUSTED_ORIGINS` include the frontend domain with `https://` prefix.

## Important Notes

- **Do NOT commit `.env.dokploy`** to git. It contains secrets.
- **Database:** Keep using Neon or migrate to a local Postgres on the VPS if preferred.
- **Backups:** Schedule regular backups of the `media_volume` Docker volume (user uploads).
- **Scaling:** This setup runs on a single VPS. For high traffic, consider adding a separate S3 bucket for media storage later.

## Rollback

If something goes wrong, you can redeploy a previous version from Dokploy's deployment history, or downgrade by reverting the git commit and redeploying.
